# Minecraft Java 版的运行基础

核对日期：2026-10-21。类名举例以 Forge 1.20.1 文档为主；旧版可能使用 World、TileEntity 等名称。基岩版创作接口不作为 Forge Java 模组的直接开发 API。

## 1. 游戏对象需要分层理解

| 概念 | 承载内容 | 对能力开发的影响 |
| --- | --- | --- |
| 注册定义 | 方块、物品、实体类型等内容的身份和共同属性 | 不能把每个玩家的状态放在共享定义里 |
| BlockState | 某位置方块的有限属性组合，如朝向、开关 | 适合有限离散状态，不适合大型技能进度数据 |
| BlockEntity | 某位置需要额外数据或运行逻辑的方块实例 | 设备库存、工作进度和网络成员信息可以在此归属 |
| ItemStack | 实际物品堆及其附加状态 | 区分“物品类型”和“这一个道具” |
| Entity | 玩家、生物、投射物等运行实例 | 有创建、跟踪、移除和重新加载的生命周期 |
| Level 与区块 | 世界维度及被加载的区域 | 能力目标和空间查询受维度、加载状态影响 |

BlockState 与 BlockEntity 的使用范围不能混同；额外数据持久化也需要相应的标记和读写路径。[方块状态](https://docs.minecraftforge.net/en/1.20.1/blocks/states/)、[方块实体](https://docs.minecraftforge.net/en/1.20.1/blockentities/)

## 2. 物理两端和逻辑两端

物理客户端是玩家启动的游戏程序，专用服务器是另一种运行程序；逻辑服务端负责世界规则，逻辑客户端负责输入和画面。单人游戏中，两种逻辑端可以存在于同一个进程，但它们仍有不同职责和线程。

不能因为代码能在单人游戏中工作，就认为它能在专用服务器中加载；服务器不存在某些客户端类。两端共享一个 static 字段也不能替代同步。[Forge 两端说明](https://docs.minecraftforge.net/en/1.20.1/concepts/sides/)

项目推导：一次操作至少区分输入意图、服务端确认的结果、客户端显示。界面上的能量条只是状态的展示，不是服务端接受施法的依据。

## 3. 模拟、渲染和真实时间

游戏逻辑 tick、客户端渲染帧和真实世界时间不能当作同一个时钟。冷却、持续效果和周期奖励需要先定义使用哪种时间；服务器卡顿、暂停或调整 tick 速率时，其表现会不同。

Minecraft 1.20.3 的官方发行说明引入了管理 tick 运行状态和速率的命令，说明“固定现实时间”和“模拟步数”需要分别考虑。[官方发行说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-20-3)

项目推导：不要用 Thread.sleep 实现蓄力或冷却。跨退出、重启和切维度的冷却，必须统一时间来源与存档语义；不能直接拿客户端帧计数或每次登录清零的计数来恢复。

## 4. 数据归属、存储和同步是三件事

| 数据 | 可能的归属 | 独立要解决的问题 |
| --- | --- | --- |
| 能力和角色资料 | 内容定义库或数据包 | 如何校验、重载、保持稳定 ID |
| 玩家成长 | 玩家附加数据或独立持久记录 | 重生、重连、旧存档迁移 |
| 多人或世界网络 | 选定世界范围的持久对象 | 成员退出、维度关系、世界关闭 |
| 正在释放的技能 | 临时执行会话 | 中断、超时、目标失效与清理 |
| 光束、粒子、音效 | 客户端表现状态 | 谁能看到、何时开始和结束 |

这张表是设计判断，不指定最终使用哪种资料格式或玩法。

Forge Capability 可以附加或暴露对象的功能，但并不默认把这些数据发给客户端；玩家死亡后的数据延续也要明确处理。[Capability](https://docs.minecraftforge.net/en/1.20.1/datastorage/capabilities/)

SavedData 则面向世界范围的数据；修改后需要通知保存系统发生了变化。它也不等于已经设计好网络同步。[SavedData](https://docs.minecraftforge.net/en/1.20.1/datastorage/saveddata/)

## 5. 世界中的对象会失效

区块可能卸载，实体可能死亡或移除，玩家可能更换维度。长期记录一个 Java 对象引用，不代表未来仍能安全使用它。空间操作还需要考虑目标是否属于相同世界，区域是否已加载，距离和视线是否符合规则。

Forge 的网络文档特别指出，直接信任客户端发来的位置可能触发任意区块加载或生成。空间请求应先校验范围和加载状态。[网络请求处理](https://docs.minecraftforge.net/en/1.20.1/networking/simpleimpl/)

## 6. 服务器判定与视觉表现

射线是否命中、何时扣资源、是否造成伤害，应有服务端确定的执行路径。可见光束可以插值、延迟或做预测，但不能用客户端光束的形状替代最终结算。

自定义实体的同步可以使用平台的实体数据机制，但官方要求只为自己控制的实体定义对应数据参数；不应任意向原版玩家类注入同一套参数。[实体同步](https://docs.minecraftforge.net/en/1.20.1/networking/entities/)

项目推导：持续技能需明确开始、持续、结束与取消；粒子、声音和手部状态也要随着取消而清理。一次发包后播放动画不足以完整表达施法生命周期。
