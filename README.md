## 当前设计方向

- 角色能力与世界内容分别推进，基础体验不互相依赖；先建立角色部分的体验。
- 可培养多名角色，每次选择一主一副搭配，更换搭配保留培养进度。
- 每名能力者可携带的技能数量有限；主修深入发展，副修掌握其他体系的有限部分，具体数量和权限待定。
- 角色档位与玩家操控上限分开；个人操控上限倾向全局共用，各角色仍需特定材料或条件独立解锁，角色与技能单独培养。
- 操控上限以科技研究与材料突破为主，实际使用经验主要用于角色与技能培养；控制重复劳动。
- 已接受铁阶段入门、主世界Lv4、跨维度Lv5、终局Lv6四段节奏，已形成三版完整候选方案，等待比较收敛。
- 能力同时服务战斗、探索、生存、建造等活动，强调体系深度和连携创造性。
- 角色获取以与原版材料、世界或怪物进程结合的科技树为重要主线，起步目标约为铁阶段，用简单技能辅助早期生存。
- 同一台随身装置持续改装，统一管理主副角色；配置只能在基地科技设施完成，外出切换保持主副关系。
- 切换有独立 CD，切换完成后可立即使用可用技能；两角色技能 CD 各自计时，持续效果按角色、技能、等级和连携方式有限残留。
- 角色与技能培养归玩家，各玩家独立，更换或借用装置按使用者自己的培养程度使用。装置有承载与性能成长空间，具体条件待定。
- 抽卡延后且不作为角色获取主要方式；装置随机词条是候选成长方向，获取、继承和属性规则待定。

这些是设计方向，尚未构成完整实现规格。原作角色身份、自建能力者身份、外观、首批角色、科技节点和数值继续讨论。

## 本机入口

在项目根目录运行，详细前提见 [工具说明](tools/README.md)：

```powershell
.\prototype-core\verify.ps1
.\tools\Invoke-ProbeGradle.ps1 build --no-daemon --console=plain
.\tools\Invoke-ProjectGit.ps1 status --short
```

规则验证需要当前命令进程能找到 JDK 工具；平台入口选择项目内 JDK 与缓存，不修改系统 Java 配置。仓库不包含便携工具、已下载游戏文件或构建产物，克隆后需要准备开发环境。
